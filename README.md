# dsh-guard-truth-lite（守真框架 · 精简版）

一个基于 DSH（DeepSeek Harness）的多智能体调度与证据审计预设。它在命令与执行之间，强行加上了「验证」这一层。

## 一、它做了什么

这不是一个大模型，而是一套 Agent 预设（Preset）配置。安装后，你的工作区会多出两个角色：

| 预设 ID | 角色定位 | 权限与能力 |
|---|---|---|
| `gt-source` | 源 Agent（主控） | 只读编排。接收用户指令，拆解后派发给子 Agent。没有 shell，没有 `write` / `edit`，无法修改你的文件 |
| `gt-worker` | 子 Agent（执行） | 负责干活。拥有 shell 和写盘权限，但无法直接与用户对话，也不具备再次派发的能力 |

**核心机制**：源 Agent 在向你交付结果前，必须审查子 Agent 的产出。没有证据（文件路径、行号、命令输出），就不算完成。

## 二、装之前必须知道

**装上它，不等于「绝对安全」。**

DSH 的强制力只有四层：

| 层 | 管什么 |
|---|---|
| 装配 | preset 挂不挂这个工具 |
| 沙箱 | 文件能写到哪 |
| 审批 | 危险动作要不要人点 |
| 运行时 | `tools/pre-execute` + `ctx.tools.guard` 拦单次调用 |

它们**全部作用于工具调用，不作用于模型输出**。模型在文字里编一个数，没有钩子能拦。

所以它拦得住什么、拦不住什么，需要分清：

- **拦不住输出层的幻觉**——写错一句话、编一个数字，这层管不了
- **拦得住子 Agent 的「假执行」**——worker 声称「已完成」但没真干，源 Agent 会去读文件核对

守真给的是**可审计性**，不是安全性。安全性靠沙箱和审批。

## 三、行为变化（你会遇到什么）

**它会变慢。** 单次对话可能变成多轮后台交互——源 Agent 拆解、worker 执行、源 Agent 回读核对。

**Token 成本会显著增加**（具体视任务复杂度而定）。多出「拆解」和「审查」两个环节，每个环节都要吃 token。

**它会频繁向你提问。** 指令模糊时它不会瞎猜，会停下来问；高风险操作会先列内容等你确认。

## 四、适合 / 不适合

**适合**：

- 有明确 SOP 的重复流程（日报、报表、定期巡检）
- 高风险操作需要人在环路（改配置、删数据、对外发布）
- 要把 AI 的决策过程留痕（教学、审计、合规）

**不适合**：

- 探索性任务，需要快速试错
- 纯对话、咨询
- 没有既定流程，需要 AI 自己发挥

## 五、四条披露义务

源 Agent 交差时必须遵守，你可以直接用这些话术来拷问它：

1. **当指令可能与你的长期利益冲突时**（比如为了本月数字好看而透支明年客流），先指出冲突，再执行或等你改口
2. **当结论证据不足时**，标「推断」，不要写成「事实」；说「其余都……」之前必须逐条验证
3. **当涉及第三方利害，或设备、数据、费用风险时**，明确点名，不要夹在正文里含糊过去
4. **转述 worker 结果时，区分「我核过的」与「我没核的」**：前者给证据（文件路径、行号、命令输出、字节数），后者标「未核验」。两者不能写成同一种笃定语气——worker 说「已完成」不是证据，读到的文件才是

这四条可以验收：翻聊天记录，看有没有说。

## 六、高危操作四类

以下四类，源 Agent 必须先拆解、核对，再派给 worker。不要直接把你的原话转过去：

| # | 类别 | 具体动作 | 要求 |
|---|---|---|---|
| 1 | 删除 / 覆盖 | `Remove-Item`、`rm`、`del`、覆盖写 | 先列内容给你看，确认了再动 |
| 2 | 系统类 | 注册表、服务、驱动、计划任务、防火墙 | 先说明影响范围，等确认 |
| 3 | 网络外发 | 往外部传数据、`git push`、带数据的 `curl` | 先说明发往哪里、发什么 |
| 4 | 批量修改 | 正则替换多个文件、批量改名 | 先试跑看命中，再落盘 |

**注意**：这四类在精简版中**没有代码级强制拦截**，靠 persona 约束加上源 Agent 的自觉。执行时人最好在边上盯着。

## 七、安装

本插件是一个 DSH **bundle**——`package.json` 里声明 `dsh.bundle.patch` 指向 `cordis.patch.yml`。不能只把 yml 丢进某个目录：必须注册进 profile，`cordis` 在启动时才会读到它。

### 方式一：插件页（推荐，桌面版只能这样）

1. `git clone` 本仓库到本地任意目录
2. 打开 DSH → 插件页 → 添加插件 → 粘贴该目录的**绝对路径**
3. 安装后**重启 DSH**
4. 新建会话，preset 选「守真 · 源」

### 方式二：命令行（仅非 desktop profile）

```bash
dsh plugin --profile <profile名> add <克隆下来的绝对路径>
```

desktop profile 被 Electron 独占，命令行装不了，只能走插件页。

### 装完怎么确认

- 新会话顶部 preset 显示「守真 · 源」
- 源 Agent 的工具集里**没有** shell、没有 `write` / `edit`

## 八、preset ID 冲突

本插件使用 `gt-source` / `gt-worker` 两个 ID。如果与你已有的 preset 冲突：

1. 编辑 `cordis.patch.yml`，把两处 `gt-source` / `gt-worker` 改成别的名字
2. 同步修改 `tool-subagent` 的 `config.agentPreset`，指向新的 worker ID

## 九、卸载

插件页卸载，或从 profile 的 `cordis.patch.yml` 中移除本 bundle，然后重启。

不残留系统级文件。

## 十、已知限制

**一，拦不住模型说错话。** 只拦工具调用，不拦生成内容。

**二，源 Agent 核对能力有限。** 它只有 `read` / `grep` / `glob`，不能跑命令重验。worker 说「脚本跑通了」，源 Agent 只能读产物文件核对，不能自己再跑一遍。

**三，每个写操作都要派工。** 固定开销，任务越碎越明显。

**四，做不了工具白名单。** DSH 在 `register()` 那一步就丢弃了工具来源信息，`ToolDefinition` 上没有 `owner` / `plugin` / `source` 字段。想做「只放行 preset 声明的工具」，没有数据基础。

**五，宿主会注入 preset 之外的工具。** 浏览器、记忆、PPT 这类 bundle 级插件注册的工具，不在 preset 的 `plugins` 行内，源 Agent 一样能看到、能调用。
